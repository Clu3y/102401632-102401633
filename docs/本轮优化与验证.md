# 本轮优化与验证

日期：2026-10-07。本文记录 lost-found 本地演示版的实际实现与验收，不代表学生个人耗时或结对分工。原 frontend、backend、作业要求、随笔、commit 记录和旧截图保留原位。

## 已确认的实现选择

- 原生 HTML/CSS/JavaScript，不引入前端框架；继续支持直接打开 `index.html`，数据仅保存在当前浏览器。
- 沿用珊瑚橙风格和分类 SVG，Logo、首页插画复用上级 `frontend/assets/` 的项目素材，副本存放在本目录 `assets/`。类别示意图不是物品真实照片。
- 电脑 ≥1024px 使用侧栏导航；平板使用顶部导航；手机主页面使用底部四栏导航，详情和成功页显示返回与主要操作。
- 列表 <640px 单列、640–1279px 双列、≥1280px 三列；电脑发布和详情分栏，手机顺序排列。输入框支持缩放，主要操作区域至少 44px。
- 每个浏览器保存一份文字草稿，不保存图片、协议或提交状态。恢复时重新选择图片、确认协议；存在草稿时，其类型优先于首页传入的类型。

## 功能与接口

搜索在关键词之外支持类别、地点、状态和排序，多条件取交集。关键词匹配名称、地点、描述与编号；地点部分匹配。条件写入 hash 地址，刷新和前进、后退可恢复。

| `LF.api.searchItems(params)` 参数 | 取值与默认行为 |
| --- | --- |
| `keyword` | 首尾去空格，忽略大小写；默认空 |
| `type` | `all/lost/found`；默认全部 |
| `categoryCode` | 现有六种类别；省略时全部 |
| `location` | 地点文本部分匹配；默认空 |
| `status` | `all/ongoing/closed`；默认全部 |
| `sort` | `newest/oldest/occurred`；默认最新发布 |
| `page/pageSize` | 保留原分页规则：从第 1 页开始，每页默认 10 条，最多 20 条 |

返回结构仍为 `records/page/pageSize/total/pages/hasNext`，同一排序字段相同时使用 id 确定顺序。原调用省略新增参数仍可使用。现有 Java 后端的账号、字段枚举、分页及上传协议不同，不能直接替换转发目标完成接入。

草稿接口为 `LF.draft.load()/save(form)/clear()`，使用独立键 `lf_publish_draft_v1`；保存类型、名称、类别、地点、日期时间、描述、联系方式和交接地点。输入停止约 500ms 后保存，离开页面和 `pagehide` 时补充保存。失败会显示未保存提示，当前表单内容继续保留。

数据库沿用 `lf_local_db_v1`，没有重置或迁移已有数据。写入在副本上执行，持久化成功后保留副本；失败恢复旧对象和编号计数。发布、状态、个人资料、登录及浏览量写入均采用此规则。

## 修复的问题

- 取消电脑端 430px 手机外框与模拟状态栏，移除禁止缩放的 viewport 设置。
- 页面 CSS 增加各自根作用域，防止详情的轮播、区块及按钮样式影响其他页面。
- 列表追加分页保留滚动位置，并提供显式“加载更多”；重新进入搜索和个人页读取当前结果。
- 新查询使用请求版本和页面连接状态检查，旧响应不能覆盖新条件或已离开的页面。
- Chrome 走查发现个人页缓存列表与异步资料刷新会移除刚打开的状态弹层；改为挂载时重新加载列表、局部更新名片，并在渲染时保留已有弹层。
- 联系弹层、确认框、头像资料弹层和图片预览支持键盘焦点约束、Esc 关闭及触发入口的焦点恢复。
- 复制降级检查实际返回结果，失败时保留可选择的联系方式输入框，提示手动复制。
- 发布成功回执按路由已解码的文字显示，名称包含百分号时不再二次解码出错；可见范围正确标为当前浏览器本地。

## 自动化与 Chrome 验收

单元测试由原 **58 项**扩展为 **73 项，全部通过**。新增 15 项覆盖组合条件、状态分组、编号查找、排序与分页、草稿恢复/清除/失败、五类写入回滚、失败重试与 URL 特殊字符。Node 测试入口自动包含新增的 `*.test.js`。

```bash
cd lost-found/单元测试
npm test
```

JavaScript 语法检查覆盖应用脚本及静态服务器。Chrome 154.0.8037.99 使用隔离、全新的浏览器上下文访问本机静态服务，以下流程实际运行通过；未读取个人浏览器数据。

| 验收项 | 实际结果 |
| --- | --- |
| 草稿 | 自动保存、刷新恢复；图片和协议不恢复；草稿类型优先于首页预设；取消清空保留内容；成功发布后清除 |
| 发布异常 | 缺必填项、损坏 PNG、未来时间均有提示；模拟数据库写入失败后保留表单，内存中不残留记录 |
| 发布成功 | 寻物和招领均成功；快速重复点击只增加一条记录；含百分号名称正常展示 |
| 搜索 | 关键词、类型、类别、地点和状态取交集；条件刷新和后退恢复；无结果与清空条件通过；模拟旧查询迟到时仍显示新条件结果 |
| 状态和个人资料 | 本人结束与恢复两种类型；刷新保留；搜索显示结束状态；昵称修改、头像上传和重新上传通过 |
| 联系与键盘 | 联系弹层获取成功；Tab 保持焦点在弹层内，Esc 关闭后回到联系入口 |
| 复制失败 | 模拟 Clipboard 拒绝与旧复制接口返回 false，提示手动复制并选中可见输入框 |
| 分页 | 首页加载至 16 条验收记录，追加后滚动位置未跳回顶部 |
| 本地 HTML | `file://` 直接打开可浏览、发布、刷新保留；从 14 条种子增至 15 条，与 HTTP 上下文的 16 条记录相互独立 |
| 页面脚本错误 | 本轮验收未捕获 `pageerror` |

尺寸矩阵共 **36 个页面场景**：六个页面分别在 360×800、393×852、768×1024、1024×768、1440×1000、852×393 下走查。检查页面与主要滚动/表单容器的横向溢出、底部栏位置以及列表列数，全部通过。852×393 为手机横屏宽度的模拟。

另以 720 CSS px 宽度验证 1440px 屏幕在 200% 浏览器缩放时的等效重排布局；这不是浏览器菜单缩放或实机捏合操作。

可重复的可选页面验收脚本是 `单元测试/browser-check.cjs`，另需 Chrome 与 Playwright；这两者不属于网页运行或上述 Node 单元测试的依赖。先在另一个终端启动本机静态服务，再执行：

```bash
# 从 lost-found 目录运行
node server.js 18790

# 在另一个终端运行；Playwright 须已安装并能被 Node 找到
node 单元测试/browser-check.cjs
```

可通过 `LF_PREVIEW_URL` 指定已启动的本机预览 URL，通过 `LF_PLAYWRIGHT_PATH` 指向已有 Playwright 模块。脚本仅修改隔离浏览器中的验收数据，但会更新本轮 `优化-*.png` 截图；需要保留这些截图时先复制，旧版截图文件不受影响。本轮预览服务仅监听 `127.0.0.1`，验收完成后停止。
